# 실행 가이드: Finesse 학교 PC 간 통신 연결

> 교실에 들고 가서 순서대로 따라 하는 문서. 마감은 **10/1(목) 회의 전**.
> 기준 데이터는 `config/pcs.json` 하나뿐이다. IP·역할·포트를 바꿀 때는 이 파일만 고치고, 스크립트는 고치지 않는다.

## 현재 확정 상태 (2026-09-28)

| 항목 | 값 | 비고 |
|---|---|---|
| 연동 LLM 서버 | **301B-11, 301B-13** | 14는 배정표상 LLM 서버지만 이번 연동에서 뺀다. 10(보조)도 제외. 나중에 넣으려면 `llmServers`에 추가 |
| 백엔드 PC | **미정** (`"backend": null`) | 26(정한비)이 후보. 단, 26은 16GB라 "16GB PC는 LLM 전용" 원칙과 충돌 |
| 8080 허용 대상 | 팀 PC 12대 전체 (`backendAllow`) | 기본값. 줄이려면 목록에서 빼면 된다 |
| LLM 방화벽 추가 허용 | 없음 (`extraLlmAllow: []`) | 기본값. 검증은 백엔드 PC에서만 한다 |
| 복원 프로그램 | 미확인 | 1단계 마커 테스트로 확인. "있음"이면 `99-reapply-all.ps1`을 추가로 만든다 |

⚠ **백엔드 PC가 정해져야 LLM 방화벽(8081)을 열 수 있다.** 허용할 IP가 없으면 `10-firewall-llm.ps1`은 아무것도 바꾸지 않고 멈춘다. 그 전에 할 수 있는 일은 **1단계(사전 조사)와 LLM PC의 3-2·3-3단계(전원 설정, llama-server 기동)**다.

## 0. 준비 (모든 PC 공통)

1. **USB에 `finesse-pc-network` 폴더를 통째로 복사**한다.
   - USB에서 **바로 실행하는 것을 권장**한다. 결과(`results/`)와 기록(`docs/`)이 USB 한 곳에 저절로 모인다.
   - 복원 프로그램이 있으면 `C:\`에 복사한 파일은 재부팅 때 사라진다.
2. **관리자 PowerShell**을 연다: 시작 메뉴에서 `PowerShell` 검색 → 마우스 오른쪽 → **관리자 권한으로 실행**.
3. 폴더로 이동한 뒤, 이 창에서만 스크립트 실행을 허용한다 (창을 닫으면 원래대로 돌아간다):
   ```powershell
   cd E:\finesse-pc-network\scripts        # USB 드라이브 문자에 맞게
   Set-ExecutionPolicy -Scope Process Bypass
   ```
   - GitHub에서 zip으로 받았다면 한 번만 `Get-ChildItem .. -Recurse | Unblock-File`을 실행한다.
4. 스크립트가 "pcs.json에서 이 PC를 찾지 못했습니다"라고 하면 `-PcId 301B-xx`를 붙여 다시 실행한다.
   - 호스트명을 확인했으면 `pcs.json`의 해당 PC `"hostname"`에 적어 두면 다음부터 자동으로 찾는다.
5. 무언가를 **바꾸는** 스크립트(`10`, `11`, `12`, `13`, `20`)는 모두 `-WhatIf`를 붙이면 바꾸지 않고 **할 일만 출력**한다. 처음에는 `-WhatIf`로 먼저 확인한다.

## 1. 사전 조사 (12대 전부, 지시서 ①)

| 순서 | 할 일 | 명령 |
|---|---|---|
| 1-1 | 조사 + 마커 파일 생성 | `.\01-precheck.ps1` |
| 1-2 | **재부팅** | |
| 1-3 | 마커 확인 (복원 프로그램 판정) | `.\01-precheck.ps1 -CheckMarker` |

- 결과는 `results\precheck-<컴퓨터이름>.json`에 저장된다. 1-3을 실행하면 같은 파일을 새 결과로 덮어쓴다.
- 마지막 줄의 **요약**을 확인한다. 위험 항목의 의미와 조치:

| 요약에 뜨는 것 | 의미 | 조치 |
|---|---|---|
| 복원 후보 N건 | 복원/동결 프로그램일 수 있는 이름이 보임 (후보일 뿐, 확정 아님) | 1-3 마커 결과로 판단 |
| 마커 사라짐(복원 의심) | 재부팅 후 마커 파일이 없어짐 | 학교에 복원 제외를 요청하거나, 재적용 스크립트(`99-reapply-all.ps1`) 방식으로 간다 → 박덕현에게 알림 |
| DHCP | IP가 재부팅 때 바뀔 수 있음 | 서버 PC(LLM·백엔드)면 학교에 IP 고정을 요청. 이 스크립트들은 IP를 바꾸지 않는다 |
| 공용 프로필 | 공용 네트워크는 인바운드가 기본 차단됨 | 규칙에 Public을 넣었으므로 그대로 둬도 된다. 프로필 변경은 따로 확인을 받은 뒤에만 |
| IP 불일치 / RAM 불일치 / GTX 1050 아닌 GPU | 배정표와 실측이 다름 | 배정표 담당자에게 알리고 `pcs.json` 수정 |
| 팀 서브넷 IP 없음 | 192.168.0.x 주소가 없음 | 랜선·어댑터 확인 |

- 12대를 다 모으면 아무 PC에서나 **PC 대장을 만든다**:
  ```powershell
  .\02-build-ledger.ps1        # → docs\PC대장.md
  ```

## 2. 백엔드 PC 확정 (사람이 결정)

`config\pcs.json`에서:
```json
"backend": "301B-26",
```
처럼 PC 번호를 넣는다. (프론트 Vite 화면을 다른 PC에서 열어 볼 필요가 있으면 `"frontend"`도 채운다.)

> 백엔드가 정해지기 전에 LLM 서버만 먼저 검증하고 싶다면, `extraLlmAllow`에 검증할 PC를 넣는 방법이 있다 (예: `["301B-12"]`). 그러면 그 PC에서 `30-verify.ps1`을 돌릴 수 있다. 다만 이것은 **LLM 서버를 여는 범위가 늘어나는 것이니 박덕현이 확인한 뒤에만** 한다. 끝나면 목록에서 빼고 LLM PC에서 `10-firewall-llm.ps1`을 다시 실행한다.

## 3. LLM 서버 PC (301B-11, 301B-13)

| 순서 | 할 일 | 명령 |
|---|---|---|
| 3-1 | 방화벽 8081 열기 (백엔드 확정 후) | `.\10-firewall-llm.ps1 -ServerExe '<llama-server.exe 경로>' -WhatIf` → 확인 후 `-WhatIf` 빼고 실행 |
| 3-2 | 절전·최대 절전 끄기 | `.\12-power.ps1 -WhatIf` → `.\12-power.ps1` |
| 3-3 | llama-server 기동 | 아래 참고 |

**3-1 방화벽**
- `-ServerExe`는 선택이다. 주면 `llama-server.exe` 전용 규칙도 만들어서, 첫 실행 때 **"Windows 보안 경고" 창이 뜨지 않게** 한다.
- 이미 그 창에서 버튼을 누른 적이 있다면 스크립트가 경고를 출력한다. 두 버튼 모두 문제를 만든다.
  - **[취소]**: 차단 규칙이 생긴다. 차단은 허용보다 우선하므로 연결이 막힌다.
  - **[액세스 허용]**: 원격 주소 제한이 없는 허용 규칙이 생긴다. 인증 없는 서버가 누구에게나 열리는 보안 구멍이다.
  - 정리: `.\10-firewall-llm.ps1 -RemoveAppRules -WhatIf`로 목록을 확인한 뒤, `-WhatIf`를 빼고 실행한다.
- 실행한 명령과 결과는 `docs\방화벽규칙목록.md`에 자동으로 덧붙는다.

**3-2 전원**
- 바꾸기 전 값은 `results\power-backup-<PC>.json`에 저장된다. 되돌리기: `.\12-power.ps1 -Restore`
- 1단계에서 "종료 관련 예약 작업"이 나왔다면 `.\12-power.ps1 -DisableShutdownTasks -WhatIf`로 목록을 본다. 학교 관리 작업일 수 있으니 **끄기 전에 박덕현에게 확인**한다.

**3-3 llama-server 기동**
```powershell
.\20-start-llm.ps1 -ServerExe '<llama-server.exe 경로>' -ModelPath '<모델 .gguf 경로>' -ExtraArgs <기존 실측 인자>
# 예시 형태 (값은 윤세연 PC의 기존 설정 그대로):  -ExtraArgs '-ngl','99','-c','2048'
```
- 경로와 인자는 **윤세연에게 기존 실측 설정을 받아서** 넣는다. 스크립트는 이 값들을 추측하지 않는다.
- `--host 0.0.0.0 --port 8081`은 스크립트가 붙인다 (127.0.0.1 바인딩이 가장 흔한 실패 원인). `-ExtraArgs`에 `--host`나 `--port`를 넣으면 스크립트가 거부한다.
- 로그는 `results\llm-<PC>-<시각>.log`에 남는다. 출력에서 다음 두 가지를 확인한다.
  - `GPU: offloaded 29/29 layers`: GPU에 다 올라갔는지
  - `수신 대기: 0.0.0.0:8081`: 빨간색 `127.0.0.1`이면 실패
- 끄기: `Stop-Process -Name llama-server`
- llama-server는 **재부팅하면 자동으로 다시 뜨지 않는다.** 재부팅 후에는 3-3을 다시 실행한다.

## 5. 검증 1~5단계 (백엔드 PC에서, 지시서 ③)

```powershell
.\30-verify.ps1
```
- LLM 서버마다 **1 ping → 2 포트 → 3 health → 4 추론**을 순서대로 확인하고, **5 순회**는 모든 LLM 서버가 통과해야 통과다.
- ping은 실패해도 계속 진행한다 (Windows는 ping을 기본으로 막는다).
- 결과 파일:
  - `results\verify-<날짜-시각>.csv`
  - `docs\검증결과표.md` (자동 갱신, 실패 칸에 원인과 조치가 적힌다)
- 실패했을 때 흔한 원인:

| 실패 단계 | 먼저 볼 것 |
|---|---|
| 2 포트 | ① LLM PC에서 llama-server가 떠 있는지 ② LLM PC에서 `netstat -ano \| findstr :8081` 결과가 `0.0.0.0:8081`인지 ③ `Finesse-LLM-8081-In` 규칙의 허용 IP에 백엔드 IP가 있는지 ④ `10-firewall-llm.ps1 -RemoveAppRules -WhatIf`로 차단 규칙 확인 |
| 3 health | 503이면 모델 로딩 중이니 1~2분 뒤 다시 실행. 그 밖에는 8081을 다른 프로그램이 쓰고 있는지 확인 |
| 4 추론 (60초 타임아웃) | GPU 오프로드 실패로 CPU에서 돌고 있을 수 있음. LLM PC 로그에서 `offloaded 29/29 layers` 확인 |

## 6. 검증 6단계: 장애 대응 (수동, 정한비와 함께)

백엔드 코드의 동작을 보는 단계라 스크립트로 판정하지 않는다.

1. 백엔드가 두 LLM 서버(11, 13)로 라운드로빈하는 상태에서 정상 요청이 되는지 먼저 확인한다.
2. **LLM PC 1대(예: 13)에서 llama-server를 끈다**: `Stop-Process -Name llama-server`
3. 백엔드로 요청을 여러 번 보낸다.
4. 기대 결과: 요청이 **실패하지 않고 11로 넘어간다** (백엔드 로그에 13 실패 → 11 재시도가 보임).
5. 13에서 `20-start-llm.ps1`로 다시 띄운 뒤, 요청이 다시 두 서버로 나뉘는지 확인한다.
6. 결과를 `docs\검증결과표.md`의 **"6 장애 대응"** 줄에 체크하고, 실패했다면 이유를 한 줄 적는다.

## 7. 재부팅 후 다시 할 것 (지시서 ③-7)

1. LLM PC·백엔드 PC를 재부팅한다.
2. 각 서버 PC에서 `.\01-precheck.ps1 -CheckMarker`를 실행해 마커를 확인한다.
3. 확인한 뒤:
   - **마커 유지됨**: 방화벽·전원 설정이 살아 있다. `Get-NetFirewallRule -DisplayName "Finesse-*"`로 한 번 더 확인한다.
   - **마커 사라짐**: 설정도 사라졌을 가능성이 높다. 3-1·3-2·4-1·4-2를 다시 실행하고, 박덕현에게 알린다 (`99-reapply-all.ps1` 제작 필요).
4. LLM PC에서 llama-server를 다시 띄운다 (3-3).
5. 백엔드 PC에서:
   ```powershell
   .\30-verify.ps1 -Label AfterReboot     # → 검증결과표 "7 재부팅 후" 열
   ```
6. 6단계(장애 대응)도 한 번 더 확인한다.
